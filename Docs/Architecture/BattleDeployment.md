# 初期配置の実装

更新日: 2026-10-26

## 章末の敵配置

- `campaign-plan.json` の `enemies` は通常IDと負の通常融合レシピIDを指定できる。保存時は通常キャラを先、融合を後とする。`positions` の順序もこれに合わせ、全員の配置を明示する。
- `StageData.enemyPool` は通常キャラだけ、`enemyFusionIds` は融合レシピだけを保持する。表示・出陣は `GetEnemies()` の同じ順序を使う。融合の能力と絵は敵レベルに合わせて共有ファクトリで生成し、レベルやレシピ変更時・ステージ破棄時に解放する。通常キャラDBへ追加しない。
- 第5/10/15/20/25/30/35/40局を章末ボスとして扱う。竜の固有行動は従来どおり竜だけが使う。敵は融合済みで現れ、レシピの自動発見は行わない。
- 敵の初期配置は重複・領域外・人数不一致を検証し、通常の章内では人数を一度に2体以上増やさない。少数精鋭の章末から次章の通常編成へ戻る場合は別として扱う。

## 融合予告の表示

- 融合素材の強調は元の淡い金色（透明度0.08）とOutlineによる輝きを使う。追加した駒スプライトの重ね描画・明滅は使わない。組合せ未確定時は従来どおり橙色で区別する。
- 強調はCellContentの固定サイズや一時点の画面サイズではなく、実際の素材マスに直接アンカーする。元の色と透明度を保ちつつ、盤面全体へ広がることだけを防ぐ。入力を遮らず、画面回転でもマスの内側に収める。
- 布陣の更新・取消・開戦時に古い枠を破棄する。`fusion-mobile`／`fusion-landscape`で回転・操作を、`fusion-border-grass-*`で未発見の草の融合予告と取消・再出陣・開戦後の枠の消去を確認する。

## 初期配置導入時の範囲（2026-10-22）

- 盤面を縦7×横6へ統一し、敵は上2段・味方は下2段・中央3段を戦場とする。
- 出陣後、戦闘を自動開始せず「布陣」で味方を選択して空きマスへ移動、別の味方と入れ替えできる。「開戦」で確定する。
- 敵はステージの敵リスト順から固定配置する。各局ごとの手作業による配置指定はまだない。
- 水は今回、中央3段で毎戦生成する。上下の配置領域を予約して保存済み布陣と衝突させない。全歩行可能セルを対象にした隠し罠は開戦後に解決し、布陣中には発動・公開しない。
- 確定配置を `KanjiBattle.Deployment.Positions.v1` に保存。同じ漢字を複数使う場合はキャラIDと同種の出現順で識別する。新しく編成した仲間の初期位置を決める前に、既存の保存位置を予約する。
- 保存の窓口は既存の `PlayerProgressStore`。保存形式バージョンや既存の育成・施設・加入データは変更しない。
- 通常の再戦は配置を確認できる。自動連戦は保存済み配置で開戦して操作待ちにならない。

## 主な所有先

- `BattleDeploymentRules`: 配置領域、既定配置、保存形式と復元・検証。
- `BattleDeploymentView`: 配置セルの入力、選択表示、開戦・編成へ戻る。
- `BattleManager`: 生成、移動・入替、確定、戦闘開始との接続。
- `BattleUILayout`: 縦長盤面が画面内に収まるサイズ計算。

## 検証と残り

`BattleRuleRegression` に上下領域、固定配置、同名複数体の復元、編成順変更、壊れた保存位置、重複・容量超過の拒否を追加。

今回の変更は配置の第一段階。新名簿・キャラ能力・通常融合・進化・超融合・プレイヤースキルは未実装。行動AIも今回の配置変更だけで新仕様対応済みとは扱わない。新しい距離・初期位置によって既存ステージの難易度が変わるため、従来の勝率・経験値ペースを合格根拠に流用しない。

ローカル確認用ビルドは `KanjiBattle.Editor.WebGLBuild.BuildLocalDeploymentPreview`。`tmp/deployment-preview/game` へ出力し、既存の `Docs/game` プレビューを置換しない。
