# UI Runtime Layout

KanjiBattle currently treats Unity prefabs as structural templates and applies most responsive presentation rules at runtime.

## Responsibilities

- Prefabs own hierarchy, component references, base text objects, buttons, scroll views, and list item structure.
- Runtime layout code owns responsive anchors, sizes, font assignment, tab placement, list spacing, and battle board sizing.
- Data/UI scripts own content population and screen-specific interaction.

## Main Runtime Layout Owners

- `FullScreenGuideView` / `GuideSettingsLayout`（初回説明・設定）
  - 既存コマと背景を使った全面表示、縦横の図・文字領域、設定項目の物理的な可読サイズを管理する。
  - 共通テーマは全面説明の文字・ボタン・画像を上書きしない。表示順と既読保存は`TutorialDirector`が管理する。

- `CastleTreeView`（城下）
  - ツリーの固定詳細欄、5枝のノードと接続線、縦スクロールを管理する。
  - 縦画面では枝タブで1列表示、横画面では5列を表示する。
  - グローバルテーマはこの配下の文字・画像・ボタン・スクロール位置を上書きしない。
  - 旧`FacilityListUI`は既存シーン参照を保ち、初回表示時にツリーへ引き継ぐ。

- `UnityUIRuntimeTheme`
  - Global canvas scaler setup.
  - Shared panel, button, scroll view, and text styling.
  - Japanese-capable TMP font assignment.
  - Bottom tab anchoring.

- `BattleUILayout`
  - Battle board/container placement.
  - Battle log area placement.
  - Battle pause/resume/back button placement.
  - Battle grid cell size, board padding, and character piece sizing.

- `JapaneseFontProvider`
  - Japanese-capable TMP font discovery and runtime fallback creation.
  - Keeps font selection separate from general theme styling.

- Screen/list scripts such as `CharacterListUI`, `FormationUI`, and `FacilityListUI`
  - Screen-specific list/card/dropdown placement and content sizing.

## Practical Rule

When a prefab visual value appears to be ignored, first search for runtime layout code before changing the prefab. In many cases the prefab value is only a safe editor/default value and is overwritten after scene load or when the screen size changes.

## When To Prefer Prefab Settings

- Component references and hierarchy.
- Static child object names that scripts search for.
- Base placeholder text.
- Event wiring that is not generated by script.

## When To Prefer Runtime Layout

- Smartphone/desktop responsive anchors and sizes.
- Font assignment.
- Repeated list item sizing.
- Battle board, log, and control positioning.
- Values that must be corrected after WebGL canvas size changes.

## Verification

After changing runtime layout behavior:

```bash
DOTNET_CLI_TELEMETRY_OPTOUT=1 /Users/yuya/.dotnet/dotnet build Assembly-CSharp.csproj --no-restore
npm run qa:visual
```

For deployment-bound changes, also run the Unity WebGL build and repeat `npm run qa:visual` against the regenerated `Docs` output.
