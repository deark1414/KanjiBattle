# 表40局の実戦測定

更新日: 2026-10-26

## 実行方法

```sh
node scripts/balance/campaign-balance.js --seeds 3 --upgrades --output tmp/balance/campaign
```

Unity Editorを開いていない状態で実行する。測定用Editorは自動起動・終了する。`-noaudio`、AudioListener停止、隔離した設定のBGM・SE無効化で無音にする。通常のゲームの音設定は変更しない。

`--stages 1,5,10`、`--profiles mixed,ranged,fusion`で対象を限定できる。`--plan-only`は実行計画の生成だけ、`--summary`は同じ出力先の測定結果を集計する。

## 測っているもの

- 実際のSampleSceneをPlayモードで動かし、BattleManagerの戦闘・移動・射線・地形・罠・支援・決着処理を使う。
- 初期レベル3、それ以降は敵と同レベル。基本編成は前衛と後衛を分け、章ごとの増枠を購入済みと仮定する。
- `mixed`と`fusion`は同じ素材枠数を使う。第21局以降、後者だけ剣＋盾を戦士に置き換える。他の16融合を代表する比較ではない。
- `--upgrades`はその局までに解放可能な全スキル強化を仮定する。費用を払える証明ではなく、育成上限寄りの戦闘性能の基準測定である。
- プレイヤースキルなし、演出確認用の確率100%設定なし。時間を加速するがダメージ・AIの別実装は使わない。
- セーブの読み書きはEditor専用のメモリ領域へ隔離する。通常のPlayerPrefsやブラウザのセーブは読み書きしない。

`plan.json`に条件、`results.json`に個別の勝敗・終了ターン・両軍残HP、`summary.json`に局別の勝数・平均ターン・時間切れ数を残す。乱数シードを記録するが、演出も共有乱数を使用するため、異なる描画環境で完全一致する保証はない。

## 育成収支

`economy.json`は各局1・3・5勝を仮定した収支。実際の加入・施設・スキル購入・経験値計算を使う。増枠とレベル上限、主力加入、訓練場、主力スキルの順に購入する一つのルートであり、全分岐の最適解ではない。

各行はその局へ初めて入る直前の状態。放置稽古・丑の経験値加算は除外する。勝利できるかは判定せず、仮定した勝利から得られる育成量だけを測る。実戦測定の同レベル・全強化条件とは別物として読む。

## 旧測定との違い

個人スキルのRuby簡易シミュレーターと`experience-pacing.js`には初期1体・縁加入・旧施設の前提が残る。現行版の勝率や必要周回数の根拠には使わない。
