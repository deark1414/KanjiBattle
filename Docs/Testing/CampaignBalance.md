# 表40局の実戦測定

更新日: 2026-10-26

**計測訂正:** 初回の測定は、一部の仮編成キャラを加入させずに出陣させたためLv1で戦っていた。`before-muted`、`counter-before`、`after-first-pass`、`after-growth`、`final-equal`の勝敗・平均ターンはバランスの根拠として無効。修正版は出陣前に加入させ、実際の全駒のレベル・HP・攻撃・防御を検証して記録する。旧結果の集計も拒否する。通常プレイの加入済みキャラの不具合ではない。

## 実行方法

```sh
node scripts/balance/campaign-balance.js --seeds 3 --upgrades --output tmp/balance/campaign
node scripts/balance/campaign-balance.js --seeds 3 --economy-wins 3 --output tmp/balance/paid
node scripts/balance/campaign-balance.js --seeds 1 --profiles mixed --playthrough --farm-wins 3 --layout adaptive --require-clear --output tmp/balance/campaign-live
```

Unity Editorを開いていない状態で実行する。測定用Editorは自動起動・終了する。`-noaudio`、AudioListener停止、隔離した設定のBGM・SE無効化で無音にする。通常のゲームの音設定は変更しない。

`--stages 1,5,10`、`--profiles mixed,ranged,fusion`で対象を限定できる。`--plan-only`は実行計画の生成だけ、`--summary`は同じ出力先の測定結果を集計する。

`--economy-wins 1/3/5`は、その回数の勝利収支で実際に購入した加入・増枠・スキル強化と、得られた共通レベルを戦闘へ渡す。`--upgrades`と併用しない。足りない加入は所持キャラへ置換し、未解放の融合を使わない。素材枠数は購入済みの枠内に制限し、実際に使った編成と育成状態を結果へ残す。依然として前の局で勝利できたという仮定のスナップショットであり、通し攻略の保証ではない。

`--campaign-ref <コミット>`は、その時点の`campaign-plan.json`の敵編成を一時コピーで比較する。アセットや本番の敵編成は書き換えない。

`--campaign-file Assets/Data/campaign-plan.json`で、アセットへ反映する前の編成案も同じ一時コピーで比較できる。

## 通し攻略

`--playthrough`は新規セーブの初期3体から実際に戦い、勝利時の本番処理で得た戦果・経験値だけを使う。任意のレベル設定、クリア済み局の先取り、所持金加算、無料加入・無料強化、放置稽古は行わない。購入ルートは`mixed/fusion`が混成、`ranged`が射撃、`spear/sentinel`が槍。加入・強化は各勝利の直後に実際に購入する。

各局は`--farm-wins`勝を目指し最大7回試行。少なくとも1勝すれば次へ進めるが、0勝ならその局で停止し、`--require-clear`付きでは失敗となる。追加の試行は別の乱数シードを使う。結果の全戦闘と、局別の勝数・試行数・到達レベル・枠・残高を`campaign.json`へ保存する。最適化された全編成の保証ではなく、一つの購入・配置方針の通し検証である。

`--layout compact`は前後衛を中央に集める基準配置、`staggered`は列をずらす配置。`adaptive`は融合解放前は中央、解放後は列をずらす。通し攻略では不要な融合を避けるため、解放後は素材を隣接させないよう配置を調整し、実際の融合ルールで検査する。開戦時に意図せず融合した場合は測定を中止する。前後列・列のずらし方も試験条件であり、全局で一つの初期配置を維持するテストではない。

## 測っているもの

- 実際のSampleSceneをPlayモードで動かし、BattleManagerの戦闘・移動・射線・地形・罠・支援・決着処理を使う。
- 初期レベル3、それ以降は敵と同レベル。基本編成は前衛と後衛を分け、章ごとの増枠を購入済みと仮定する。
- `mixed`と`fusion`は同じ素材枠数を使う。第21局以降、後者だけ剣＋盾を戦士に置き換える。他の16融合を代表する比較ではない。
- `--upgrades`はその局までに解放可能な全スキル強化を仮定する。費用を払える証明ではなく、育成上限寄りの戦闘性能の基準測定である。
- プレイヤースキルなし、演出確認用の確率100%設定なし。時間を加速するがダメージ・AIの別実装は使わない。
- セーブの読み書きはEditor専用のメモリ領域へ隔離する。通常のPlayerPrefsやブラウザのセーブは読み書きしない。

`plan.json`に条件、`results.json`に出陣直後の全駒の実レベルと能力、勝敗・終了ターン・両軍残HP、`summary.json`に局別の勝数・平均ターン・時間切れ数を残す。C#で指定レベルとの一致を検証し、Node側でもJSONの成長式と照合する。不一致や欠落は失敗として終了する。乱数シードを記録するが、演出も共有乱数を使用するため、異なる描画環境で完全一致する保証はない。

## 育成収支

`economy.json`は各局1・3・5勝を仮定した収支。実際の加入・施設・スキル購入・経験値計算を使う。増枠とレベル上限、主力加入、訓練場、主力スキルの順に購入する一つのルートであり、全分岐の最適解ではない。

各行はその局へ初めて入る直前の状態。放置稽古・丑の経験値加算は除外する。勝利できるかは判定せず、仮定した勝利から得られる育成量だけを測る。`--economy-wins`ではこの状態を戦闘に渡すが、前の局の勝利は仮定のまま。`--playthrough`だけが仮の勝利を使わず、実際に進んだセーブを次の戦闘へ引き継ぐ。

## 旧測定との違い

個人スキルのRuby簡易シミュレーターと`experience-pacing.js`には初期1体・縁加入・旧施設の前提が残る。現行版の勝率や必要周回数の根拠には使わない。

## 修正版の確認

- `tmp/balance/verified-levels/`は加入・実レベルを修正した最初の36戦。第10/13/15局は、同レベル・解禁済み強化条件の混成編成で各3/3勝。前回の「+3レベルでも突破不能」という評価は撤回する。
- 初回の7局の取り巻き削減は無効な測定に基づいていたため、そのまま最終調整とは扱わない。購入済み育成と変更前編成を使った再比較で採否を判断する。
- `original-paid-three`では変更前の第7/8/9/12/13局を、3勝分の購入済み育成で混成・射撃とも各3/3勝。第15局は混成2/3・射撃3/3勝。これら6局の過剰な弱体化を戻す。第10局は変更前に両編成0/3勝だったため、武器3種と弓を残し、二の取り巻きだけを削って5体から4体へ変更。
- `gates-paid-three`では調整後の第10局が混成・射撃・戦士条件で各5/5勝。第25局は混成0/5・射撃5/5・戦士1/5勝。`gun-placement`では混成を列ずらしへ変更するだけで2/5勝へ変化。第25局は貫通射撃への対策が効く関門として維持し、キャラ能力・経験値・回復量は変更しない。これらの標本は勝率の確定値ではない。
- `campaign-verified`は新規セーブからの通し攻略。混成・非融合・プレイヤースキルなし、各局3勝、レベルや所持金の上書きなし。40局すべて突破し、129戦120勝9敗、平均7.94ターン、最長17ターン、20ターン時間切れ0回。素材の所持・出陣枠・初期実能力を全129戦で検証し、意図しない融合が0であることも確認した。第40局進入Lv33、3勝後Lv34・8枠。勝率一般の保証ではなく、一つの実在する購入・配置ルートの確認である。
- 同通し攻略で追加試行が必要だったのは第8局4戦、第24局4戦、第25局5戦、第36局6戦、第38/39局各4戦（いずれも3勝）。他の局は3戦3勝。前半の集中配置を固定していたわけではなく、融合解放後に素材を離して列をずらす配置へ切替えている。常に分散する配置では第9局で7連敗する別試行もあり、回復役の隣接と貫通対策を両立する必要がある。
- 育成収支の3勝仮定では、第10局進入Lv10、第20局Lv19、第30局Lv26、第40局Lv33。5勝仮定は第40局Lv37。敵Lv35に対して、経験値が常に大幅に不足する曲線ではない。ただし勝利前提の収支であり、その回数での攻略保証ではない。
- レベル差による逆転幅、全加入ルート、全17融合、無強化・部分強化、プレイヤースキルを含む通し攻略は継続課題。数シードの勝数を確定勝率とは扱わない。
- 最終データでUnityの戦闘回帰・データ整合・WebGLビルドに成功。ブラウザで初期3体の第1局クリアと第12局の敵前後衛配置を確認。Nodeの測定条件3件と既存テスト基盤11件も成功。
