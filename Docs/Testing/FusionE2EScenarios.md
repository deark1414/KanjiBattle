# 通常融合の操作シナリオ

更新日: 2026-10-24

## 目的と範囲

通常融合を増やす前に、隣接配置・競合選択・開戦・戦闘終了・再戦・保存をまたぐ共通動作を固定する。
Playwrightが実際の画面をクリックし、Unity側から取得した状態と照合する。
ボタン操作を関数呼び出しで代用しない。準備用コマンドは初期データ・局面条件の設定に限定する。

対象は実装済みの双剣・散弾。残る通常融合15種、進化・超融合、図鑑画面は対象外。
勝率、難易度、音の聞こえ方、演出の良さ、全キャラの性能を保証するテストではない。

## 環境

- Unity 6000.4.4f1とWebGL Build Support。
- Node.js、プロジェクトのPlaywright、Playwright用Chromium。
- 2026-10-23の環境確認では追加インストール不要。Unity実行ファイルは`UNITY_EDITOR`で変更可能。
- Unity MCPはこの自動実行の必須条件ではない。Unity Editorで同じプロジェクトを開いたままバッチビルドしない。

新しい環境ではリポジトリ直下で`npm ci`、`npm run install:browsers`を実行する。

## 実行

```sh
npm run qa:e2e:doctor
npm run qa:e2e:list
npm run qa:e2e:unit
npm run qa:e2e:build
```

`qa:e2e:build`は専用WebGL版の作成から全シナリオの実行まで行う。
既に作成済みでコード変更がなければ`npm run qa:e2e`で再実行する。
コード変更後は再ビルドが必要。通常プレビューのビルドでは代用できない。

```sh
npm run qa:e2e -- --only fusion-save-reload
npm run qa:e2e -- --only fusion-selection --headed
```

対象を絞ったビルドと実行は`npm run qa:e2e:build -- --only fusion-selection`。
失敗が1件でもあれば終了コード1。ビルド未作成・テスト用操作口不在も失敗として扱う。

## データ分離

- `KANJI_BATTLE_E2E`を専用ビルドだけに追加。通常版のスクリプト定義は変更しない。
- 出力は`tmp/e2e/game`。普段の`tmp/deployment-preview/game`や公開用`Docs/game`は上書きしない。
- テスト用サーバーは空きポートを自動確保し、終了時に停止。
- 各シナリオは独立した一時ブラウザ環境を使う。普段のブラウザ、実機、Unity Editorのセーブを変更しない。
- 再読込シナリオだけは同じ一時環境内で保存の永続化を確認する。
- 固定シード1729。通常ケースは第40局突破済み・軍師Lv20・6枠・素材`二/剣/二/剣/三/銃`。
- 融合施設の条件確認のみ第19局突破から開始。第20局突破・戦果不足・必要額到達を順に確認。
- 戦闘用ステージは既存第21局を実行時に複製し、敵1体・罠なし・増援なしにする。制作データは変更しない。
- 勝利ケースは敵Lv1、敗北ケースは敵Lv2000。性能調整ではなく終了経路を再現するための専用条件。
- 連戦は初戦を実際に勝利させ、次戦の敵レベルだけを試験用コマンドで変更して実際の敗北・停止まで確認する。

## シナリオ一覧

| ID | 操作・条件 | 合格条件 |
| --- | --- | --- |
| fusion-gate | 融合解放前に隣接配置し、突破条件と費用を確認 | 未解放では融合・予告なし。第20局と必要費用で施設解放可能 |
| formation-navigation | 素材を離して開戦し、戦闘中の接近と再戦を確認 | 非融合のまま戦闘し、接近しても融合しない。再戦では6素材と離隔配置を復元 |
| fusion-selection | 隣接・斜め・離隔へ実際に移動 | 隣接時だけ線と`2→1`・未知結果`？`を表示。開戦前は人数不変・未発見。非競合なら選択ボタンなし |
| fusion-cancel | 配置を変え、開戦せず編成へ戻る | 未確定の配置・発見を保存しない |
| fusion-origin | 縦に隣接させて開戦 | 前側の素材位置に出現。編成枠の素材数は維持 |
| fusion-win-retry | 独立した2組を隣接配置し、勝利・再戦 | 選択画面なしで双剣・散弾となり6素材が4体に。再戦で6素材と同じ融合予定を復元 |
| fusion-save-reload | 競合から中央の組を選択、確定後に再読込 | 同じ配置・選択・発見を保持し、同じ組で再開できる |
| fusion-corrupt-save | 不正保存を用意し、素材が競合する配置にする | 開戦は保留。候補を選択して解決し、素材の二重使用不可。「選び直す」では未確定へ戻る |
| fusion-party-change | 保存後に編成順を変更 | 旧競合指定を流用せず未確定として確認。離して置けば競合・融合とも解除 |
| fusion-defeat-retry | 融合体を含む味方が全滅、手動再戦 | 戦闘中は分離せず、所持不変。再戦で元の6素材に復元 |
| fusion-repeat | 隣接配置で開戦・連戦ON、勝利後の自動再戦、次戦敗北 | 同じ配置から融合を再判定し、配置待ちを挟まず再戦。敗北で停止 |
| fusion-mobile | 390×844で隣接配置・予告・開戦 | 線と予定を確認でき実クリックが届く。キャンバスは画面全体を使う |
| fusion-landscape | 844×390で同操作 | 横長でも同じ操作が成立する |

## 判定と記録

画面内ボタンの矩形をUnityから取得し、キャンバスの表示サイズに変換してクリックする。
ボタンが非活性か、スクロール領域で隠れているかも検査する。
Unityのイベント判定で別のUIに覆われているボタンへのクリックは失敗として扱う。
戦闘状態の待機は条件付きで行い、一定時間で終了しなければ失敗にする。
ブラウザ例外・Unity実行時例外が出たケースも失敗とする。

結果は`tmp/e2e/results/index.html`と`report.json`。
各シナリオに画面PNG、最終状態JSON、コンソール記録、Playwrightの操作記録`trace.zip`を保存する。
失敗時は`failure.png`も保存する。

```sh
npx playwright show-trace tmp/e2e/results/fusion-selection/trace.zip
```

既存の配置9項目は`node scripts/visual/check-deployment.js`。
ダメージ・射程・融合素材の厳密な条件と能力値計算はUnityの`BattleRuleRegression`が担当する。

新しい融合を実装した際は共通13シナリオを再実行し、固有能力のUnityテストを追加する。
UI変更時はこの操作テストに加えて実画面を確認する。キャンバスが収まることだけでは文字の重なりや美観は保証しない。
CIでの定期実行・全ステージ巡回・収益化や公開サービスの確認は別途導入する。

UI整理時の確認項目として、布陣パネルに隠れる再生操作（速度・連戦）がある。
現状の連戦シナリオでは開戦後にONにする。布陣中にも操作させる場合はレイアウト変更と専用シナリオを追加する。
縦長の融合一覧は操作できるが文字が小さいため、可読性は次のUI整理で改善する。
