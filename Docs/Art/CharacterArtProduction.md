# キャラクターのコマ・モチーフ制作

対象: 通常26系列、通常融合17種、敵専用の竜、砂の分身。未実装の進化・超融合・究極融合は対象外。

初回制作・実装コミット: `54f285e`。以下の表現方針はユーザーレビュー後のドット絵改訂版。

現行方針（2026-10-25追加レビュー後）: 以前のモチーフ20組は元画像を維持する。コマは以前の木地・墨文字・五角形・敵の下向き形状に戻す。文字が変わっていない15系列は元画像をそのまま使用し、新規・名称変更・融合は同じ意匠で512px描画する。新規25モチーフは64pxから128pxの論理グリッドへ変更し、既存画像に合わせて細部を残す。甲・弓・酉の旧モチーフ（鎧・矢・鳥）も前指示どおり維持。

## 表現方針

- コマは以前の五角形・木地と墨文字・淡色の縁取りを継承。味方は上向き、敵は下向き。朱塗り・白文字と融合専用の二重枠は廃止し、以前の意匠へ統一する。
- 漢字の形と意味が主役。一文字は大きく、二文字は縦組み。HP・向き・レベル表示の場所を確保する。
- モチーフは和風の透過ドット絵。通常はコマ、召喚時は大きく出現して消え、軍勢・編成では選択時のみ表示する。
- 既存モチーフ20組は`reviewed-motif-crops.json`に記録した画像・UV範囲・縦横比・回転を維持する。現行の表示倍率1.18は維持し、コマと表示タイミングを変えない。残る25組は新規ドット絵を使い、砂の分身は本体と同じ砂の絵を使う。
- 新規モチーフは原画の内容領域を128pxの論理グリッドへ収め、補間なしで512pxへ拡大する。既存20モチーフへはこの処理を適用しない。コマは以前と同じ512px、文字・縁取りは平滑な描画を維持。UnityではコマはBilinear、モチーフはPoint。
- 砂は砂山・砂粒のキャラクター。人型やゴーレムにせず、分身も表示名は「砂」とする。「砂偶」は使用しない。スキル名は「砂の分身」で、分身の性能・生成条件は変更しない。
- コマは元の生成処理を参照した`render-classic-pieces.js`とYuji Boku書体で描画する。元画像を使う15系列は一切描き直さない。新規の二文字は縦組み。ライセンスを同梱する。
- 双剣は既存の剣に合わせた青緑の直線的な両刃剣2本。戦士も同じ直剣を装備。磁石は赤いU字型と銀色の極。賽子は数字キャラに合わせた木製・茶色の目に変更。
- 修正原画は内蔵image_genによる編集。参照・全プロンプト・原画保存先は`CharacterArtRefinements.json`、原画は`Assets/Art/Generated/CharacterMotifsReviewed/`に保存。既存画像や前案は削除しない。
- 賽子は前段で形状と目の重複を修正。最新レビューでは各面の2・3の目を面内の対角線へ揃えた`DiceDiagonal.png`を採用。画面上の単なる斜めの列ではなく、面の頂点から反対側の頂点への線を基準とする。上面では奥と手前の頂点を結ぶ方向に並ぶ。配置ガイドは`References/DicePipPlacement.png`、最終画像の編集は内蔵image_genで実施。
- 影は人型・顔・手足を廃止し、平たい暗色の影へ簡素化（`ShadowSimple.png`）。繭は葉・草・枝のない白い蚕の繭（`SilkwormCocoon.png`）。灯は行灯ではなく一本の蝋燭（`Candle.png`）。雨は雲を除き、雨粒と小さな波紋だけ（`RainNoCloud.png`）。キャラ名・スキル・性能・コマは変更しない。
- 追加レビューで鈴は無地の真鍮製へ変更し、模様・赤い紐・房飾りを除去（`BellPlain.png`）。糸は白糸と木製糸巻きだけにし赤い結び紐を除去（`ThreadPlain.png`）。牛のモチーフは丑で使用中の画像を対象とし、手綱・房飾りを除去（`OxPlain.png`）。山は丸みのある稜線、左が急で右が長くなだらかな左右非対称へ変更（`MountainNatural.png`）。散弾はラッパ状の古式銃ではなく、3つの銃口が見える三銃身・木製ポンプ式へ変更（`ScatterPumpTriple.png`）。他の画像と性能は変更しない。
- 歪み修正後に135画像の検査とUnity取込、`art-dice`の召喚・コマへ戻るテスト（1/1）を再確認。記録は`tmp/e2e/dice-geometry/`と`tmp/character-art/dice-geometry-comparison.png`。前段の7件通過とは別の、賽子だけの追加確認。
- 通常ローカル版も更新し、PC・スマホ縦長・横長の描画と実行時例外なしを再確認。今回は画像と制作記録のみを変更し、性能・戦闘ルール・コマは変更していない。

## 再生成・確認

1. `node scripts/art/build-character-art.js`でカタログと新規分を再生成する。旧モチーフ20組を優先して参照する。コマは同名の旧画像があればそのまま使用し、それ以外は旧意匠で描画する。素材は保存済みのため、再生成に画像APIは不要。
2. Unityの`KanjiBattle.Editor.CharacterArtImporter.ImportProduction`で取込・参照を確認する。
3. `node scripts/art/check-character-art.js`で135画像の読込、旧20モチーフの参照・UV等の一致、新25モチーフの128pxグリッド、旧15系列のコマの元画像との一致、一覧の全読込・分類・拡大・スマホ表示を確認する。旧モチーフやコマにドットのグリッドを強制しない。
4. `node scripts/art/serve-gallery.js`で一覧を開く。

ゲーム内確認はE2Eの`art-standard`、`art-dice`、`art-sand-mobile`、`art-selection`。一覧と編成枠の同じキャラは同時に召喚されることがあるため、表示数を1に限定せず、選択したキャラ以外のモチーフが出ていないことを確認する。召喚後は元の漢字コマへ戻る。

繭の保護表示は漢字へ文字を重ねない金色の枠へ変更。敵用コマは朱塗り・白文字で、通常コマと融合コマの両方を用意した。
