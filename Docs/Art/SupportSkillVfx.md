# スキル画像草案（25種類）

状態: 素材レビューを経てローカルゲームへ接続。HTMLは独立した動作見本。既存のモチーフ・コマ・スキル性能は変更していない。実装範囲と検証は[ゲーム接続記録](SupportSkillVfxIntegration.md)を参照。

- 保存先: `Assets/Art/Drafts/VFX/SupportSkills/`。有効素材は計36枚（既存再利用15枚を含む）。電・糸・砲弾・共用槍は512×128、風・波は512×256、甲羅は256×256、その他は512×512。128px論理グリッドを補間なしで4倍表示。通常は単画像を動かす。炭は状態別2画像、賽子は出目別6画像を切り替える明示的な例外で、連番アニメシートは使わない。
- 共用剣・槍・盾は`VFX/Weapons/SwordMotion.png`、`VFX/Animated/Spear/frame_03.png`、`VFX/Animated/Shield/frame_02.png`。丑は`UI/PieceMotifs/Ready/Motif_30.png`。いずれも`Assets/Resources/`内の元画像は変更しない。新作は山の石片`Source/MountainRebound.png`。甲の数値表示・丑の経験値・回復値は独立した動作例で、実際の戦闘結果ではない。
- 賽子は`Assets/Resources/UI/PieceMotifs/Motif_01.png`～`Motif_06.png`の内容を変えず再利用。元画像のコピーを`Source/DiceFace1.png`～`DiceFace6.png`に保存し、SHA-256も記録する。装飾専用シードで切替列と最終出目を決め、毎フレーム・停止中・方向変更では引き直さない。再生ループまたは最初から再生で新しい列となる。約0.98秒で確定し、2.8秒のレビュー周期終了まで同じ画像を保持。光が消えても出目は読める。回復は既存水滴、防御・攻撃は既存波紋の表示時着色を流用する。旧3個組の賽子`DiceBody.png`は履歴として保存し、現在の動作例では使わない。
- 炭の燃焼状態は既存`Assets/Resources/UI/PieceMotifs/Ready/Motif_F1009.png`を再利用。消火状態は同じ配置・構図から赤熱だけを取り除いた編集画像。被弾後0.5秒で燃焼へ切り替え、火の粉は0.95秒までで消えるが燃焼画像はレビュー周期終了まで維持する。本番の被弾条件やバランスは変更しない。
- 雨の水滴は`Assets/Resources/VFX/Animated/WaterHeal/frame_03.png`、要塞の砲弾は`Assets/Resources/VFX/Animated/Gun/frame_02.png`を再利用。元ファイルは変更せず、草案用コピーだけを同じ出力規格に整える。新規素材の原画・プロンプトと、再利用素材の元パスはJSONに記録。
- 原画は同ディレクトリの`Source/`。内蔵image_genによる生成元、全プロンプト、生成時の保存先は`SupportSkillVfx.json`。
- 磁石はU字磁石から発する半円波紋へ変更。新原画は`Source/MagneticRipple.png`。旧鉄粉`Source/MagneticPull.png`・旧磁力線`Source/MagneticFieldLines.png`と生成記録は保持。磁石本体は`Assets/Resources/UI/PieceMotifs/Ready/Motif_F1007.png`、ハンマーは`Assets/Resources/VFX/Weapons/HammerMotion.png`を変更せず再利用する。
- 鍛冶の赤熱は表示時の着色で、コマ画像自体は変更しない。プレビューでは0.7秒で叩き、接触後に赤熱、2.4秒で元の色へ戻る。磁石は0.25秒から波紋を発し、0.75秒から引き寄せる。これらはレビュー用秒数でありゲーム性能を定めない。
- `layout.json`に固定寸法・内容範囲・中央ピボット・接続点を記録。電と糸のローカル前方は右。透明余白まで距離に含めず、内容範囲を接続点へ合わせる。鈴・巻き付き・繭は対象の中心基準で、絵の縦横比を保つ。繭は中央を空け、漢字を見せる。
- 波紋は元の音符なし`Source/BellEcho.png`を再利用し、初回の波紋PNGとのバイト一致を確認。独立した音符の原画は`Source/BellNote.png`。音符一体型の前案`Source/BellEchoNotes.png`も制作記録と共に保持。
- 音符1枚を2～3個複製し、発動ごとに位置・大きさ・傾き・開始の遅れを変える。外側へゆっくり移動して消え、漢字の周囲42pxを空ける。プレビューの装飾専用シードを用い、毎フレームや方向変更で散り方を引き直さない。一時停止時の再描画は同じ絵を維持し、再生ループまたは最初から再生で別の散り方になる。ゲーム側の乱数・技能確率は変更しない。
- 繭のレビュー再生は巻き付き、短い消去区間、保護状態、ループ用フェードで構成。演出の重なりはなく、巻き付きだけが残る表現ではない。プレビューの秒数は実ゲームの効果持続ターンを定めるものではない。
- HTML上の動きは独立したレビュー用シミュレーション。ダメージ、乱数、スキル確率、実際の引き寄せ成否は解決していない。プレビューの成功をUnityへの接続確認と読み替えない。

## 再生成と検査

```bash
node scripts/art/build-support-skill-vfx.js
KANJI_ART_PORT=8799 node scripts/art/serve-gallery.js
node scripts/art/check-support-skill-vfx.js
```

画像検査: 36枚のRGBA透過、非空、四辺の余白、固定寸法、4pxブロック整合、波紋・繭中央の実質透明な空間（アルファ最大1/255）、再利用元15枚の未変更を確認する。鍛冶の叩く→接触→赤熱→冷却と、磁石の波紋→引き寄せの順序も検査する。賽子は100発動で6出目の網羅、画像キーと出目・効果の一致、停止中の固定、確定後の保持、6枚の表示画像が異なることを検査。炭は消火→燃焼と火の粉消失後の燃焼維持を検査する。

画面検査: 25種類のスキルの4方向での動作変化、PC1280px・スマホ390pxの非空描画、画面のはみ出しなし、画像の縦横比、再生関連の操作とスキルへの直接移動を確認する。賽子は6出目の効果分類を検査。音符は40発動のばらつき、2～3個の個数、漢字への重なりなし、4方向での見切れなし、停止中の固定・再生時の変化を確認する。風鈴も40発動・3対象の音符の見切れなしを検査。繭は420時点で巻き付きと保護が同時表示されないこと、保護状態が後の時点でも維持されることを確認する。鉄の3形態、甲の着弾→肩代わり、山の被弾→返還の順序も検査。記録は`tmp/skill-vfx/report.json`、画面画像も同ディレクトリ。

追加・変更キャラの演出は25系統中25系統が草案済みで、未制作0系統。承認・ゲーム接続・実戦確認は別工程。集計範囲・全件の内訳は`SkillVfxProgress.md`を参照。

Unity素材の取り込み・戦闘ルール回帰・データ検査と、ローカルE2E用WebGLのビルドを実施。公開サイトのデプロイは行っていない。実戦の同時表示や細かなタイミングの調整は継続する。
