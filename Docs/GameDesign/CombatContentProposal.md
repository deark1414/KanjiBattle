# KanjiBattle 戦闘・キャラクター具体化案

作成日: 2026-10-13 / 更新日: 2026-10-19 / 状態: 個別レビュー反映中

融合レシピの最新の章別比較は [FusionRecipeWorkshop.md](FusionRecipeWorkshop.md) を参照。通常融合推奨12案と比較・冒険・超融合を合わせて60案に広げた検討資料で、以下の既存候補を自動廃止・採用するものではない。

同日追加の命名レビューで、当面の動詞／動作主体の命名と、素材からの説得力に欠ける概念を候補から除外した。現在の候補状態は上記資料の第0節を優先する。本資料に残る砕・潤・熔等は過去の発想の履歴であり、現在の有効候補として扱わない。

進化名は1文字、通常融合・超融合名は2文字も可と再確認。具体的な存在を表すために双剣・溶岩・石弾なども比較できるが、個別レシピの採用は未決定。禁止基準は文字数にかかわらず適用する。

最新の採用: 一＋二＋三→賽、二＋剣→双剣（性能は未決定）。剣＋剣→双／双剣は廃止し、下の旧F01・旧件数を現在の有効候補として扱わない。三＋銃→散弾は追加候補。レシピ状態は章別検討帳の第0節を優先する。

追加キャラは、進化前後を無理に用意せず最初から進化相当の単独キャラとして出す選択肢も認める。初期セット全員の進化は維持。既存の進化・超融合と共通の切り札1枠を使う方式を推奨するが、取得経路・時期・素材区分などの細則は未決定。個別キャラへの適用は未承認。

戦士シリーズの素材・結果を採用: 剣＋盾→戦士（通常融合）、刀＋鎧→武士、鎧＋兜→将軍（後2つは超融合）。各2枠、超融合は共通の進化枠を使う。将は将軍へ名称を更新。性能・兜の取得／区分は未決定。3段階進化や連続融合の追加ではない。

2026-10-20追加採用: 壁→城、盾＋壁→要塞（通常融合・2枠）。性能は未決定。最新版の全キャラ・進化一覧と融合網羅の確認は [CharacterRosterSummary.md](CharacterRosterSummary.md) を参照。数字9種類の削減も検討中だが、最終名簿や削除は決定していない。

## 0. この資料の扱い

- 合意済み仕様の正本は `CurrentGameDesign.md`。本資料は、その方針を実装可能な形へ具体化する提案であり、新しい名称・レシピ・数値を確定しない。
- 現行の `characters.json`、`skills.json`、射程・数字ルール・スキル実行コードを確認して作成した。ゲームのデータやセーブは変更していない。
- 現行の通常25体（数字9・武器3・防御3・遠距離3・自然4・動物3）を出発点とする。追加レビューで動物の基本形を十二支表記へ変え、辰→竜を導入する方向。目標版の人数・ID・登場局は再整理が必要で、現行25体を固定上限とはしない。現行の竜は加入不可のボスとして記録し、味方版との性能分離を設計する。
- 候補は外部ゲームや辞書の調査結果ではない。漢字の採用理由はゲーム内の連想であり、辞書的な同義・上下関係を保証しない。難読字・異体字は採用前に意味・字体・表示を確認する。
- レシピ一覧は制作者向け。ゲーム内の未発見レシピ・融合結果は、合意どおり伏せる。

### 初回レビューの反映

- 遠距離の現行「矢」（ID17）は、基本名を「弓」、進化先を「弩」にする案へ更新。まだ現行データは矢のまま。採用時はIDを維持し、表示・説明・演出との整合を確認する。
- 槌の進化先は鎚から斧へ変更する案。道具の普遍的な上下関係ではなく、重い一撃を担う役割の継承として設計する。
- 盾の進化は鎧へ整理し、盾系の固有能力は自己軽減に集約する。反射は壁系へ分離する。現行の通常キャラ「鎧」の代替名は旗を採用。防御ステージに合わせ、能力は周囲の味方の防御を高める支援案を検討する。対象範囲・自己適用・重複・倍率は未決定。
- 壁は砦／城を進化候補にする。動物系は午→馬・酉→鳥・寅→虎へ整理し、辰→竜も導入する。馬→象は取り下げ、鷹・獅は将来の3段階目か独立キャラとして保留。進化前の動物は融合不可。馬＋竜→麒麟は超融合候補へ変更する。
- 表編のラスボスは竜。辰→竜の2段階最終戦は検討案で、HP・継戦・再開・報酬などは未決定。裏編のラスボスとは分ける。
- 木の進化先は樹ではなく森を採用する。通常融合の木＋木＋木→森は名前が重複するため保留。木＋木→林も森と存在が近いため候補から外す。空いた分を機械的に別レシピで埋めない。
- 初期セットは全員進化、追加キャラの進化は任意とする。兜の進化・能力は未定で、行動阻害耐性案は再検討。兜＋鎧→将は検討案。超融合素材に限る進化複数体の許可は確定し、戦闘開始時に1体へ融合し、戦闘中の進化・超融合は合計1体までとする。解除時は進化1体制限へ戻して編成確認を行う。
- 以下は合意した変更方向と未承認の個別提案を併記している。ゲーム本体の変更・バランス検証は未実施。
- 2026-10-19: 十・拾を融合結果の候補へ追加。各章に関連する融合を1〜3個程度、章跨ぎも含めて検討する。数合わせのノルマにせず、融合施設の解放を前倒しする意味でもない。

## 1. 最初に固める戦闘の土台

### 設計上の推奨

1. 役割を成立させる通常行動と、確率で起きる追加効果を分離する。確率を一律100%にする変更ではない。
2. 通常行動を確実にした分、現在のスキル倍率・貫通・防御無視をそのまま全て常時化しない。射程・威力・対象数を一緒に調整する。
3. 配置と射程が機能する小さな戦闘を先に検証し、その同じ戦闘で融合と非融合を比較する。
4. 25体の全名称を決めることより、「このキャラを採用する理由」が実戦で成立することを優先する。

### 基本行動案（個別射程・追加効果は未採用）

距離は斜めも1。直線は縦・横・斜めの8方向。以下の「確実」は、有効な対象・経路がある場合を指す。移動は通常最大1、動物最大2。味方越し・水越しの可否は正本の規則に従う。

### 数字の扱いの提案（要レビュー）

- 進化後も元の数字系列に所属させる。例: 壱は低位数字として扱う。
- 種類判定では一と壱を同じ基底種類と数え、進化だけで種類数を水増ししない。一だけの判定も基底種類を使う案。
- 融合した素材は盤上にいないため、素材の数字種類数をそのまま残さない。融合結果が数字系に属するかは結果キャラごとに定義する。
- これは既存パッシブと新要素の接続案。採用するまでは現在の数字処理を変更しない。

F02は盾→鎧、F08は木→森への変更に伴って保留。F07の林は候補から除外。F10は進化前の動物が融合不可となり通常融合から除外し、超融合側へ移す。元の12案のうち通常融合として有効な案は8組、保留2組、除外・移動2組であり、12組を必ず揃えるという意味ではない。表21の候補はF01・F03・F04・F05の4組となる。F01・F03は表20までに素材が登場済み。F04・F05は表21で石と出会い、加入後に使える。同素材複数を必要とするレシピは、同じキャラの複数編成が可能な既存方針を利用する。

### 候補の注意点

- 十・拾は追加の融合結果候補。五＋五→十を通常融合、伍＋伍→拾を超融合とする案なら、数字の組み合わせから結果を連想できる。複数進化素材の例外は確定したが、素材・区分・能力はまだ提案。元の12案の集計とは別に、追加結果候補2種として管理する。十→拾の単体進化や十を素材にする連続融合は決めない。
- 各章に関連する候補1〜3個程度を密度の目安とし、異なる章の素材同士も組み合わせる。章跨ぎレシピは重複して総数へ数えない。表1〜20の素材の融合も、表20突破後の施設開設から利用する。
- 木→森は進化。木＋木→林は候補から除外し、木＋木＋木→森の旧案は保留。同じ木の増量表現を融合にも必ず用意する必要はない。
- 雲は火＋水の連想を使うが、どの能力にするかは自由度が高い。まず回復系で検証し、攻撃・回復の両方を同時に最強にしない。
- 燧・熔・潤は分かりやすさに注意が必要。字の印象と実際の能力が結び付かなければ名前かレシピを差し替える。
- 礫の範囲投射、雲の広域回復などは新しい能力案。現行コードにあることを前提にしない。
- 一＋一→二など、通常加入と融合発見が同じキャラを指す案は初期候補に含めない。加入・発見・復元・図鑑の混乱を避けるため、採用するなら別途設計する。
- 元の12案には数字素材がなかったが、追加候補の十・拾で数字融合を検討する。既存パッシブとの相互作用を検証し、結果の数字分類・種類判定・性能を決める。
- 超融合レシピは、進化先と通常融合の役割が固まった後に設計する。名前だけ大量追加して通常融合の再上位版にしない。
- 馬＋鳥→天馬、馬＋竜→麒麟は超融合候補。午＋酉など進化前の動物を使う通常融合案は除外。複数進化素材の例外は確定したが、個別の素材・結果・能力は検討中。現行解放順では動物の融合は裏10突破後の超融合施設開設からとなる。加入時期・ボスとの性能分離も設計し、通常融合の初期8組へ数えない。
- 盾の軽減を鎧へ引き継ぐ設計は通常融合ではなく進化。旧F02を無断で超融合に移さない。

## 4. 強さの検証方法

### 現行データから見える注意点

施設・パッシブ等を含めない素のLv.25値（HP / 攻撃 / 防御）:

| 漢字 | Lv.25 | Lv.30 | Lv.35 |
|---|---|---|---|
| 剣 | 240 / 136 / 32 | 265 / 156 / 37 | 290 / 176 / 42 |
| 盾 | 396 / 68 / 58 | 441 / 78 / 68 | 486 / 88 / 78 |
| 矢 | 240 / 131 / 30 | 265 / 151 / 35 | 290 / 171 / 40 |
| 銃 | 230 / 165 / 29 | 255 / 190 / 34 | 280 / 215 / 39 |
| 火 | 288 / 126 / 32 | 323 / 146 / 37 | 358 / 166 / 42 |

数値は `基本値 + 成長値 × (Lv - 1)` で計算。勝率・実ダメージの試算ではない。例えば剣の攻撃はLv.25→30で約15%増えるが、与ダメージには防御や倍率が関わる。「相性で5レベルを返す」を固定倍率だけで保証しない。

銃は現行の素の攻撃が矢より高く、スキル側には別の威力補正がある。遠距離の確実化だけを先に行うと、毎行動の期待火力が変わる。矢・銃・火の通常行動威力、射程、追加効果を同時に比較する。

### 融合の最初の試験値案

- 2体融合: HPは素材の合計付近、攻撃は素材攻撃の合計付近を探索の始点にする。防御は合計せず、高い素材の防御を基準に探索する。
- 3体融合も同じ考え方。ただし回復・範囲攻撃・反撃・阻害による貢献まで含めて調整する。
- 上記は採用式ではない。行動1回への集中、反撃回数、過剰ダメージ、防御の適用回数などで、単純合計と実力は一致しない。
- 融合で回復／妨害の担当が消える場合は、その機能の不足も評価する。攻撃数値を足しただけで「2体分以上」と判定しない。
- 回復不能な連続拘束、素材2体より低い実効貢献、どの相手にも融合一択になる状態をいずれも不合格とする。

### 最初の検証セット

| 試験 | 比較するもの | 合格の考え方 |
|---|---|---|
| 前衛・後衛 | 盾＋矢を前後配置／逆配置／横並び | 想定する相手で配置が生存と火力に影響する |
| 射程 | 矢・銃・石・槍を味方／水の後ろに配置 | 正本どおりの通過・遮断、射程内で無駄に前進しない |
| 回復 | 水＋耐久役、全快、重傷、回復対象なし | 最低HP割合を優先し、回復不要なら攻撃する |
| 通常融合 | 剣2体／双、槍＋盾／陣 | 得意な状況では融合の強さが出て、分散戦では非融合に理由がある |
| 3体融合 | 正式候補を再設計後、素材3体／2体融合＋1体／3体融合を比較 | 集中・分業の違いが出る。3枠消費と出撃人数を正しく表示する |
| レベル差 | 同一敵・同一乱数条件で差0／5／10 | 有利編成は差5を返せる事例、特に有利なら差10を返せる事例を持つ |
| 不利と成長 | 不利編成を差0／5／10で比較 | レベル差が大きければ不利側も勝てる。相性が絶対判定ではない |
| 進化枠 | 基本／進化1体／超融合1体 | 切り札の影響が出るが、残り編成が不要にならない |

勝率評価は各条件で複数の固定乱数種を共通使用し、勝敗・残HP・決着ターン・キャラ別戦績を残す。具体的な試行数・勝率基準は検証環境を整えた後に決める。通常局は固定地形で差を測る試験と、地形を含むランダム試験を分ける。

旧軽量シミュレーターは古いレベル上限などの仮定が残るため、新設計の合格根拠には使わない。現行の経験値試算も旧加入条件・表Lv.50までが前提。モデル更新前に裏の最終Lvや加入変更後の必要周回数を断定しない。

## 5. 育成曲線を決めるための入力

次の3プロファイルで、戦果の使い道と加入周回を含めて比較する。戦闘に勝てることを仮定した経済試算と、戦闘勝率の試験を混同しない。

| プロファイル | 想定 | 確認する問題 |
|---|---|---|
| 少数加入 | 気に入った役割だけ加入させて進む | 加入を絞ると経験値不足で長時間足止めされないか |
| 選択的収集 | 各章で数体を加入させる | 通常の加入周回で必要な育成が進むか |
| 全加入 | 登場した全種類を集める | 早期の上限張り付きで報酬の楽しみが消えないか |

- 勧誘所は未強化約10勝、最大強化5〜7勝へ更新し、早期加入の抽選は除く。中間段階の閾値・費用は試算入力として候補を比較する。
- 施設の開設・攻撃HP強化・レベル上限・経験値効率が同じ戦果を取り合う。新施設の開設費用を決める前に、経験値だけ最適化しない。
- 表の敵レベルをそのまま裏へ延長して先にLv.100を決めない。裏の編成・進化の性能と、成長の余地を一緒に評価する。
- 経験値係数の調整は、加入周回込みで数勝の追加育成に収まるかを評価して提案する。現時点では係数・最終上限の新しい数値を確定しない。

## 6. 実装を分ける単位と検証順

| 順 | まとまり | 作るもの | 次に進む条件 |
|---:|---|---|---|
| 1 | 通常戦闘の基盤 | 縦7×横6、初期配置、固定敵配置、基本行動と追加効果の分離 | 前後配置・射程・水／味方越し・動物移動が検証できる |
| 2 | 作戦と振り返り | プレイヤースキル、戦績、完全な作戦保存、加入条件更新 | 再戦・連戦で作戦再現、勝利時だけ実績が増える |
| 3 | 通常融合の一通り | 素材／基点／実行の選択、開始時融合、復元、図鑑、施設 | 初回も拒否可能、未知結果は伏せる、枠と素材が消失しない |
| 4 | 表の内容と調整 | レビュー後の複数レシピ、表40局、育成・施設経済 | 融合／非融合双方で攻略でき、加入と数勝の追加育成が機能する |
| 5 | 進化と裏前半 | 25体の進化データ、個別実績・試練、裏1〜10 | 切り札1体制限、既存育成の引継ぎ、試練の再現性 |
| 6 | 超融合と裏後半 | 専用レシピ、裏11〜20、育成上限拡張 | 進化枠を維持し、通常融合と違う使い分けが成立する |

最初の動作確認に少数の融合を使うことと、公開版のレシピを1組だけにすることは別。公開版は複数の作戦・発見が成立する数を揃え、上の通常融合候補8組と追加の数字候補を出発案とし、保留2組は必要性から再検討する。除外した林や超融合へ移した天馬の代替を機械的に追加しない。

保存は各機能の後付けにしない。基盤着手時に通常キャラ・出撃個体・形態・レシピを区別するIDと移行方式を設計し、既存セーブを読み込む回帰試験を用意する。公開版では非対応形式を理由に全消去する現在の処理をそのまま採用しない。

## 7. まとめてレビューする観点

次の確認では1体ずつ名前を質問せず、次の3束で変更希望を集める。

1. 通常行動と射程: 矢・銃の直線4、火・石の周囲2、水の回復射程2と自己回復、槍の通常単体／追加貫通。
2. 進化: 動物は午→馬・酉→鳥・寅→虎・辰→竜へ整理。辰の登場・加入と表ラスボス竜を設計する。通常鎧の代替名は旗を採用し、防御支援能力と進化先の幟を提案する。数字の大字化・基底種類判定も含む。
3. 融合レシピ: 通常融合候補8組・数字の追加候補、動物の超融合候補をまとめて選定する。各章1〜3個程度は目安で、個別レシピの承認とは分ける。集中型／分散型の使い分けも検証する。

名称や射程の承認を、性能数値の検証合格とは扱わない。ゲームの核や14テーマの合意数は、この提案を作っただけでは変更しない。
